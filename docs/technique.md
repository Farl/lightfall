# 2D 平光原圖 → 2.5D 光影氣氛：技術拆解

參考：[@vux429 的 Threads 貼文](https://www.threads.com/@vux429/post/De7EVP5GFse)，他用 Godot 做一個橫捲場景，把平光的像素原圖加上光影特效。

## 1. 從貼文看得出什麼

截圖裡的除錯 UI 幾乎就是他的功能清單：

| UI | 推測用途 |
| --- | --- |
| `1 原始 / 2 柔光調色 / 3 電影氣氛` | 三組調色/後製 preset，「原始」等於完全繞過光影 |
| `D 日間 / N 夜間`、`09:00` 時間滑桿 | 時間決定光的方向與顏色 |
| `強度 100%` | 處理後畫面與原圖的混合比例 |
| 場景細節、光束、浮塵、流動霧、柔焦、膠片顆粒、色散 | 各自獨立開關的效果層 |
| `動態空氣`、`P 暫停動態` | 霧/塵的動畫時鐘 |
| 畫面上的十字點、虛線、`直射光落點` | 手動放置的幾何控制點，可拖曳光的落點 |

作者在留言補充：**純 2D 幾何運算，沒有用任何 3D 功能**，**不需要做低模**，但**需要一些模擬 2.5D 的幾何光影資料**。

結論：原圖不變，另外標註一份很輕量的「代理幾何」（窗戶開口、地板/牆面平面、家具的大概體積），光影全部在 2D 畫面上用這份資料算。

## 2. 這個原型的做法

```
roomData.ts（代理幾何 + 調色盤）
        │  同一份資料畫三次
        ▼
 Canvas2D: albedo（平光原圖）  depth（1/w）  normal  emissive
        │
        ▼  lighting.frag  @ 640×360
 每個像素：從深度重建世界座標 → 對窗戶開口 + 方盒做解析式 shadow ray
          + 光束 ray-march + 霧 + 浮塵 + 天花板燈
        │
        ▼  blur.frag（下採樣 + 高斯）
        ▼  final.frag @ 1280×720
 色散 → bloom / 柔焦 → ACES → 調色 → 暗角 → 顆粒 → 與原圖依「強度」混合
```

### 2.1 代理幾何（＝「2.5D 幾何光影資料」）

全部是最簡單的形狀，都在 [`src/scene/roomData.ts`](../src/scene/roomData.ts)：

- **房間殼**：地板、天花板、三面牆，是一個單點透視的盒子。
- **貼花（decal）**：牆或地板上的矩形，例如畫框、門、地毯、窗框。
- **方盒（box）**：家具的體積。有 `hidden` 的方盒只投影不畫，例如植物葉子的陰影代理。
- **窗戶開口（pane）**：光只能從這些矩形穿過，窗簾遮住的部分不算。
- **燈的位置**。

對手繪原圖來說，這份資料就是美術或工具要額外標註的東西，通常十幾個方盒就夠。

### 2.2 用 Canvas 漸層畫出精確的深度圖

透視投影下，平面多邊形上的 `1/w` 在螢幕空間是 **仿射（affine）** 的，所以只要一條 `createLinearGradient` 就能精確畫出整個面的深度，不需要 3D rasterizer。做法見 `layers.ts` 的 `affineDepthStyle`：用三個頂點解 `v = a·x + b·y + c`，再沿 `(a, b)` 方向從最小深度拉到最大深度。

深度、法線、自發光都經過同一個 `fillPolygon`，所以畫家演算法的遮擋順序在四張圖裡一定一致。

### 2.3 像素級光照（`lighting.frag`）

1. **重建位置**：`P = camera + viewRay(px) * w`，與 `camera.ts` 的投影對稱。
2. **直射光**：從 `P` 往光源射線，先求它跟窗戶平面 `x = windowX` 的交點，看有沒有落在 pane 裡，再跟每個方盒做 slab test。光源方向在小圓盤內抖動多次取樣，就有柔和的半影。
3. **光束**：沿著相機射線，從房間近端走到表面，每一步做同一個能見度測試並累積散射。用射線穿過窗戶的位置當 noise 座標（模擬「髒玻璃」），同一塊玻璃照出的光就共用同一個值，自然形成一條條光柱。
4. **浮塵**：CPU 模擬世界座標的粒子，用同一套能見度判斷（`lighting.ts` 的 `lightVisible`）分成「在光束裡」與「不在」兩個通道。
5. **流動霧**：fbm noise，越低越濃、越遠越濃，並往光束密度裡加變化。
6. **燈**：點光源加一條 shadow ray。

整個場景只有約 20 個方盒，每個像素直接全部跑一遍，不需要 shadow map 或 BVH。

### 2.4 時間與光

`config.ts` 的 `TIME_KEYS` 是一天中的關鍵影格（光色、強度、環境光、天空色、燈），循環線性內插。`CELESTIAL` 決定太陽/月亮的仰角與方位角弧線。拖曳「直射光落點」會反推光的方向，蓋過時間算出的方向；再動時間滑桿就恢復。

## 2.5 原圖可以換成任何畫

光影只依賴深度、法線、自發光這三張由代理幾何產生的圖，albedo（顏色）可以整張換掉。這個原型用 AI 把平光原圖重繪成細節更多的像素畫（`scripts/ai-repaint.mjs`），提示詞特別要求「平光、不要陰影與光束」，讓它像一張 base color 貼圖。因為構圖沒變，原本的代理幾何仍然對得上，光影照樣成立。

這也說明了這個做法的分工：**美術只管畫平光原圖，光影交給幾何資料**。

## 2.6 樹林與迴廊：剪影圖層

另外兩個場景用同一套光照，只換「光從哪裡進來」和「什麼擋住光」：

- **開口一般化**：光只能從一個開口進來。房間是左牆的窗戶（`x = 牆`），樹林是最後面的天空平面（`z = 深度`），迴廊是左牆的拱廊。shader 的 `lightVisible` 只看開口的軸與位置，其餘相同。
- **剪影圖層（`OccluderLayer`）**：一片平面上的 2D 形狀，例如樹幹、分岔的樹枝、葉團，或窗花的直櫺、尖拱、圓窗。同一組形狀做兩件事：
  1. 依透視畫成多邊形，就是畫面上看到的剪影。
  2. 在平面自己的 (u, v) 上點陣化成一張遮擋貼圖。shadow ray 穿過這片平面時，在交點取樣，透光量乘上 `1 - 遮擋`。

  所以畫面上的剪影和擋住光的形狀一定一致。
- **小孔成像的模糊**：每個縫隙都是一個小孔，投下的光斑是太陽圓盤的投影，離平面越遠越大越糊。貼圖有 mipmap，取樣時 `lod = log2(到平面的距離 × softness × 每單位 texel 數)`。
- **樹林（逆光）**：太陽低低地掛在樹後面，朝鏡頭照。遠、中、近三層剪影，光要依序穿過每一層的縫才照得到，光柱會從太陽的位置放射出來。空氣加了前向散射（Henyey-Greenstein，`phaseG`），越朝太陽看越亮；透過樹縫看得到天空的地方，畫出太陽圓盤和光暈。
- **迴廊（窗花）**：左牆兩層。一層是反轉的，形狀是尖拱開口，其餘是實心牆；另一層是窗花石條。陽光從中庭照進來，把窗花的圖案投到地板和光柱裡。窗花很細，所以這個場景的太陽圓盤（`sunSoftness`）比較小，圖案才不會糊掉。
- **AI 原圖**：樹林與迴廊也用 `scripts/ai-repaint.mjs forest`、`scripts/ai-repaint.mjs cloister` 重繪。剪影與窗花的位置沒變，所以光影照樣對得上。

## 3. 換到 Godot 4 會怎麼做（推測）

作者用的是 Godot，原生功能可以對應到同樣的分層：

| 這個原型 | Godot 4 2D |
| --- | --- |
| normal 圖 | `CanvasTexture` 的 normal map（手繪或從代理幾何烘焙） |
| 窗戶的直射光 | `DirectionalLight2D` / `PointLight2D` + `height` 參數 |
| 方盒陰影 | `LightOccluder2D` 多邊形（它是 2D 投影，沒有高度，所以要更真實的「2.5D」投影還是得自己寫 shader） |
| 光束、霧 | `CanvasItem` shader 加 `SCREEN_TEXTURE` / `BackBufferCopy` |
| bloom、調色 | 啟用 HDR 2D 後用 `WorldEnvironment` 的 glow 與 adjustments，或自訂後製 shader |

作者特別強調「2.5D 幾何」，加上落點拖曳點，比較像是自己寫的投影 shader，而不只是內建的 Light2D。

## 4. 已知限制與可以再做的

- 深度只有 8 bit，靠 `normalBias` 壓掉 acne；改用 16-bit（兩個通道）或直接在 GPU 光柵化就能解決。
- 光束在暗面上有抖動顆粒感（每像素 jitter）。可以加 temporal accumulation 或用半解析度算再模糊。
- 房間裡植物的葉子陰影還是實心方盒。可以改用剪影圖層（2.6 節），做出葉縫光斑。
- 代理幾何是手寫的。現在已經可以在畫面上拖曳、抬高、新增方塊，但還不能存檔；下一步可以存成 JSON。
- AI 重繪後家具位置會有些微偏移，代理幾何需要依新圖微調才能完全貼合。
